# Assignment Compliance Checklist

Every requirement specified in the ReachInbox / Outbox Labs Software Development Intern Assignment specification is evaluated below with its exact implementation, test mechanism, status, and verification evidence.

---

| Requirement | Implementation | Test | Status | Evidence |
|---|---|---|---|---|
| **NO CRON** | No `node-cron`, `cron`, OS crontab, Agenda, or polling loops. Time-based scheduling is delegated exclusively to BullMQ delayed jobs (`opts.delay`). | Codebase static analysis & test suites confirm zero cron dependencies. | **PASS** | `grep -r "cron" backend/src` yields zero scheduling cron references. Delayed jobs are queued via `emailQueue.add(..., { delay })`. |
| **BullMQ Delayed Scheduling** | `backend/src/queue/queue.ts` initializes BullMQ `Queue` instance; `scheduler.service.ts` calculates `delay = targetSendTime - Date.now()` and calls `emailQueue.addBulk()`. | `api.test.ts`, `restart.test.ts` | **PASS** | BullMQ schedules jobs into Redis ZSET. Jobs are picked up and executed when due. |
| **Redis Infrastructure** | Redis 7 container with `--appendonly yes` persistence in `docker-compose.yml` on port 6379. | Health check & BullMQ connection verification | **PASS** | `docker compose ps` shows `reachinbox-redis` healthy. `/health` endpoint returns `redis: "healthy"`. |
| **Relational Database (PostgreSQL)** | PostgreSQL 16 container on port 5434 with Prisma ORM models (`User`, `Email`) and composite indexes. | `prisma migrate dev` & schema validation | **PASS** | Durable tables `User` and `Email` with foreign keys and indexes created in PostgreSQL. |
| **Ethereal SMTP Integration** | Nodemailer transport in `backend/src/services/email.service.ts` using verified credentials with automatic fallback. | `worker.test.ts`, `scripts/test-smtp.ts` | **PASS** | Real test emails sent; Ethereal generated message IDs and web preview URLs (e.g. `https://ethereal.email/message/...`). |
| **Google OAuth Authentication** | Real OAuth 2.0 flow using `google-auth-library` (`/api/auth/google`, `/api/auth/google/callback`, `/api/auth/me`, `/api/auth/logout`) + dev-login fallback. | `api.test.ts` & integration tests | **PASS** | Sets secure HTTP-only JWT session cookie. Unauthenticated requests are rejected with 401. |
| **Scheduled Emails Tab** | Frontend table in `App.tsx` and `EmailTable.tsx` backed by `GET /api/emails/scheduled` with live 4s polling. | Manual & automated API pagination test | **PASS** | Shows pending and processing emails with sky blue and amber badges. |
| **Sent Emails Tab** | Frontend table in `EmailTable.tsx` backed by `GET /api/emails/sent`. | Manual & automated API pagination test | **PASS** | Displays delivered emails with exact `sentAt` timestamps, attempt counts, and green badges. |
| **CSV / Text Upload & Parsing** | `frontend/src/lib/csvParser.ts` parses comma, semicolon, tab, and line-separated leads with header skipping. | `csvParser.test.ts` (5/5 passed) | **PASS** | Displays detected count badge (e.g., `✓ 113 valid addresses detected, 7 invalid rows ignored`). |
| **Delay Between Emails** | Supported in `POST /api/emails/schedule` (`delayBetweenEmails`); staggers send times: `effectiveSendTime = startTime + i * delay`. | `scheduler.service.ts`, `api.test.ts` | **PASS** | Staggered delays verified in DB `scheduledAt` column and BullMQ job delay calculations. |
| **Hourly Rate Limiting** | Redis-backed atomic Lua script in `hourlyLimiter.ts` scoped to `rate:{sender}:{YYYY-MM-DDTHH}`. | `rateLimiter.test.ts` (4/4 passed) | **PASS** | Atomic slot claiming up to limit. On 4th send with limit=3, returns `allowed: false` and `msUntilNextHour`. |
| **Rescheduling on Limit Hit** | When hourly limit is hit, worker never drops or fails email; updates DB `scheduledAt` and enqueues BullMQ delayed job for next hour. | `worker.ts` and `rateLimiter.test.ts` | **PASS** | Database status remains `SCHEDULED`; BullMQ delayed job registered for next window. |
| **Configurable Worker Concurrency** | `WORKER_CONCURRENCY` environment variable drives BullMQ worker concurrency setting. | `worker.ts` default 5 concurrency | **PASS** | Worker scales across parallel threads without blocking queue operations. |
| **Idempotency Guard** | 1. Deterministic job IDs (`jobId: email.id`).<br>2. Status check for `SENT`.<br>3. Atomic conditional update `UPDATE Email SET status = 'PROCESSING' WHERE id = :id AND status = 'SCHEDULED'`. | `worker.test.ts` (idempotency tests) | **PASS** | Second concurrent worker gets `claim.count === 0` and is denied execution. Duplicate jobs skip sending. |
| **Server Restart Persistence** | Redis AOF stores delayed jobs. Relational DB stores email records. Workers resume delayed stream upon restart. | `restart.test.ts` (1/1 passed) | **PASS** | Scheduled future job survives complete worker process shutdown; restarted worker sends email on time. |
| **1000+ Email Scenario** | Bulk DB insert (`createMany`) + pipelined BullMQ enqueue (`addBulk`) in chunks of 500. | `api.test.ts` 1000-recipient test | **PASS** | 1,000 emails scheduled and enqueued in **323ms** without blocking the API response thread. |
| **Loading States** | Table skeleton rows with Tailwind shimmer animations in `EmailTable.tsx`; spinner in Compose modal. | Frontend UI inspection & build | **PASS** | Skeletons render during data fetching; submit button displays loading state while scheduling. |
| **Empty States** | Contextual empty state illustrations and call-to-actions in `EmailTable.tsx`. | Frontend UI inspection | **PASS** | Displays custom graphics and "Compose Batch" shortcut when queue or history is empty. |
| **Error Handling & Feedback** | Zod validation with 400 bad request error details; frontend toast banner notifications. | `api.test.ts` validation test | **PASS** | Rejects invalid payloads; toasts auto-dismiss after 4.5 seconds. |
| **Typed API Client & Props** | Fully typed interfaces in `frontend/src/types/` and `src/lib/api.ts` with strict TypeScript. | `npm run typecheck` across monorepo | **PASS** | Zero `any` shortcuts; `typecheck` passed with 0 errors across backend and frontend. |
| **Reusable Components** | Modular architecture: `Header.tsx`, `EmailTable.tsx`, `ComposeModal.tsx`, `LoginView.tsx`. | Code review & component reuse | **PASS** | `EmailTable` reused for both Scheduled and Sent views with dynamic props. |
| **README Documentation** | Comprehensive README covering setup, architecture, trade-offs, and operations. | `README.md` created in root | **PASS** | Contains Mermaid diagrams, Docker setup, Ethereal instructions, and architecture breakdown. |
